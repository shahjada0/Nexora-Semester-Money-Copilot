# Decisions log

Decisions made during the build. Ones you made are marked **(team)**; the rest are mine, with the reason.

| # | Decision | Reason |
|---|---|---|
| 1 | **(team)** Brand: "Semester Money Copilot by Nexora", using the Nexora logo mark (cropped to `public/logo.png`). | Team decision. |
| 2 | **(team)** Deploy to Vercel. On Vercel the SQLite file lives in `/tmp` and is seeded on cold start. Run the live final locally (`npm run dev`). | Vercel's bundle is read-only. `/tmp` state is per instance and can reset, which is fine for a sandbox demo but not something to rely on in a live final. |
| 3 | _(Superseded by #25: Gemma 4 on the Gemini API is now the default; Groq stays as the alternative.)_ Default LLM `openai/gpt-oss-120b` on Groq (Apache-2.0); `openai/gpt-oss-20b` is the alternative. `llama-3.3-70b-versatile` was listed on console.groq.com on 2026-10-18 but returns 404 for our project key, so it is not offered. gpt-oss runs with `reasoning_effort: low` to keep each turn small. | Permissive licence and strong tool calling. Swap it with `GROQ_MODEL`. |
| 4 | `better-sqlite3` with raw SQL, no ORM. | Fewer moving parts and synchronous transactions, which suits the hash chain (no forks under concurrency). |
| 5 | All money is integer minor units (pence/poisha). | No floating-point drift in the ledger or the limits. |
| 6 | PDF text extraction with `unpdf` (MIT, serverless build of pdf.js). Fixture PDFs are generated with `pdf-lib` (MIT). | Works on Vercel without native deps. The extractor deliberately returns white or hidden text too, so injection attacks are visible to the scanner. |
| 7 | Next.js 14.2.35 is pinned per the spec. `npm audit` reports advisories against Next ≤ 16.3 and against dev-only tooling (vitest, eslint-config-next, tailwind's chokidar). | The spec mandates Next 14. Listed in the known-risk list in `docs/SECURITY_SELF_ASSESSMENT.md`. |
| 8 | Injectable clock (`lib/clock.ts`). | Tests and the eval suite advance time to check the 24 h rolling limits and the cooling-off timer without waiting. |
| 9 | Sandbox bank details use a fictional `99-xx-xx` sort-code range and `GB00SAND…` IBANs, which fail the real IBAN checksum. | Nothing can be mistaken for a real account. |
| 10 | The audit log is mirrored to `<db>-audit.jsonl`. SQLite triggers reject UPDATE and DELETE on `audit_log`. | Append-only is enforced in the database itself, and the two copies must agree for `verifyChain()` to pass. |
| 11 | Account numbers and IBANs are masked to their last 4 digits in the audit log. OTPs and tokens are never logged. | Privacy by default, even in a sandbox. |
| 12 | Rolling 24 h limits count payments to **saved payees** only. Payments to verified institutions (tuition) are excluded. | Tuition is always Tier 3 anyway. Counting it would push every £5 payment that day into Tier 3 for no security gain (found while testing the split-payment demo after a tuition proposal). |
| 13 | Pending, unexpired proposals count toward the rolling limits at proposal time; only executed payments count at execution time, and the tier can rise between the two. | Stops "propose ten at once" splitting without double counting at execution. |
| 14 | `blockOnSuspiciousInstructions = true`: an invoice with instructions aimed at the agent cannot be paid, even if its bank details are correct. | A document carrying hidden instructions is itself compromised. The student gets a clean copy from the portal. |
| 15 | Default funding: the UK GBP account if it covers the amount, otherwise the family's BDT account via the cheapest licensed provider by true cost. The funding route is part of the confirmation binding. | Puts the true-cost comparison inside the tuition flow, and the funding route cannot be swapped after confirmation. |
| 16 | Family approval is opt-in per payment (the "Ask Abbu to approve" button). Once requested, the gate requires it. `POLICY.requireFamilyApprovalForTuition` can make it mandatory. | Keeps the hero demo short while still demonstrating dual control. |
| 17 | Scam check = rules + optional LLM, and the **higher** risk wins. Only "high" places 24 h gate blocks; "medium" warns. | The LLM can add caution, never remove it. Blocks only ever restrict. |
| 18 | The scam rules were tuned on `fixtures/messages/messages.json`; `holdout.json` was written afterwards and never used for tuning. Both are reported. | Honest numbers: the dev set over-states real-world accuracy. |
| 19 | Eval runs on a pinned clock (2026-10-18 09:00 UTC) and the FX snapshot. `npm run evidence` runs the demo on the real clock with live FX (falling back to the snapshot). | Reproducible metrics, plus real-time execution evidence. |
| 20 | Every number in a doc table is generated (`<!-- AUTO:… -->` blocks, filled by `npm run docs:sync`, which `eval` and `evidence` call). | Docs cannot drift from the measured results. |
| 21 | The scripted planner (no API key) and the LLM go through the same `runTool` → gate path. | The demo works on stage without network access, and the security results do not depend on the model. |
| 22 | Semester plan: transfers in two tranches (D−28, D−14) that finish at least 10 days before each deadline, via the cheapest provider at today's rate. | Reduces the chance of converting everything on one bad-rate day; leaves time for the transfer. A simple, explainable rule rather than a rate forecast. |
| 23 | Eval and evidence pace live LLM calls (`EVAL_LLM_PACE_MS`, default 8–12 s) and score the model only on answers it actually gave; fallbacks are listed separately. | The Groq free tier allows about 8k tokens/min. A first unpaced run hit 429s, and the app correctly fell back to the rules parser, but scoring those fallbacks as model errors would misstate model accuracy. |
| 24 | The system prompt tells the agent not to make payment-safety decisions itself but to call `proposePayment` and let the gate decide. | The gate is the safety layer, and the demo should show it. In testing, gpt-oss still sometimes declines obvious scam payments on its own, which is acceptable defence in depth; the gate block is proven in eval A5. |
| 25 | **(team)** Switched the default LLM to Google's Gemma 4 via the Gemini API (native function calling, plain `fetch`, no new dependency). Groq stays as an alternative (`LLM_PROVIDER`). | Team request. Measured on 2026-10-18: `gemma-4-31b-it` took 28–49 s per call (and rejects `thinkingLevel`), `gemma-4-26b-a4b-it` with `thinkingLevel: minimal` took about 1.2 s. An agent turn is 2–3 calls, so the default is 26B-A4B; 31B is one env var away. Both are Apache-2.0 per the official Hugging Face model cards. The provider honours Gemini's `retryDelay` on per-minute 429s and echoes thought signatures with function calls. |
